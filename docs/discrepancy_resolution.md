# Resolution of the audited discrepancies

The [finding matrix](discrepancy_resolution.csv) and [course requirement matrix](requirements_traceability.csv) map the original audit to implementation and evidence.

The new authoritative task is binary, with explicit weak elapsed-time labels. It replaces the old 414-segment three-class benchmark rather than relabeling its scores as fatigue detection. All metric functions explicitly use [0,1]. The mandatory majority and RMS+MDF logistic baselines are separate models. The numerical feature schema now connects preprocessing, model fitting and actual recarga/inference, including distinct abstention reasons. Borg/Cerqueira results are not imported.

F31 macro-F1 0.740 and F55 0.7164 are historical cuts of another task. Their historical difference is not assigned an invented cause. They are retired from the main comparison, and a newly frozen binary run supplies every current table. The manuscript and code are generated from that one run; the additional RAR remains a separately recorded source.

The 140-file archive and 20-file RAR are not assumed to contain 17 different people. Cross-source identity remains unknown. Folder-derived groups are declared, both legs stay together, and duplicate byte/canonical signal content is rejected. This addresses preventable leakage while preserving the remaining person-identity uncertainty.

Calibration, RAW/RECT/ENV channel mode, resting baseline, MVC, Borg, video, actual load/cadence and failure markers cannot be recovered from the CSV columns. They are marked unavailable or unverified, and are not invented to complete a table. The same applies to balanced student contributions and authorship attestation. These are evidence limitations, not software discrepancies that a higher model score can resolve.

The independent code review found five robustness defects. Regressions reproduce them and verify corrected run binding, duplicate-signal guards, rejected-interval inference, failure audits and bounded archive extraction. Full results require a completion receipt that binds the exact feature table and output files; interrupted or edited runs cannot generate a report as if complete.

The original four input files and the original Git checkout are retained. This independent repository records the implementation history under the authenticated account; it does not fabricate other contributors or rewrite the old history.
